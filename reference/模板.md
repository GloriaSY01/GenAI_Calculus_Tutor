文献 1
Boosting Large Language Models with Socratic Method for Conversational Mathematics Teaching
1. 论文核心内容
 这篇文章研究如何将苏格拉底式教学方法引入大语言模型的数学教学场景中，使模型不再直接输出答案，而是通过对话一步步引导学生思考。文章提出了一个面向数学教学的 SocraticLLM，并结合额外知识增强模型回答的可靠性和教学质量。

2. 与我们项目最相关的设计点
 这篇文献和我们项目中 右侧 AI tutor 的引导式交互设计 高度契合，特别对应以下几个点：
不直接给答案，而是逐步引导
agent回复需要有教学阶段感，而不是普通聊天
agent在数学场景下要兼顾“引导性”和“正确性”
3. 可借鉴的核心机制
将 tutoring 拆分为更明确的教学环节，如 review、heuristic、rectify、summarize
在数学场景中引入知识增强，减少模型幻觉
用结构化的教学流程替代单纯 prompt 限制
4. 对我们项目的启发
 我们目前的agent已经实现了基础的 Socratic prompt 约束，但还比较粗。参考这篇文章，后续可以把 agent 的对话策略细化成更明确的教学阶段，例如：
先回顾知识点
再提出启发式问题
对错误思路进行纠正
最后做总结
   这样可以让我们的agent更像“真正的教学tutor”，而不是简单的问答机器人。
5. 这篇文献支撑的项目设计点
M1 Dialogue Manager
M2 Guided Response Generator
explain-to-unlock / 苏格拉底式交互逻辑设计

文献 2
LPITutor: an LLM based personalized intelligent tutoring system using RAG and prompt engineering
1. 论文核心内容
 这篇文章提出了一个基于 LLM 的个性化智能辅导系统 LPITutor，通过引入 RAG 和 prompt engineering，让系统能够根据学生的问题、能力水平和知识需求生成更准确、更清晰、更符合难度要求的回答。
2. 与我们项目最相关的设计点
 这篇文献和我们项目中 Agent 模块后续接入 RAG 的方案高度相关，特别对应以下几个点：
agent回答需要依赖外部知识，而不是只靠大模型内部常识
agent回答不仅要正确，还要适应学生水平
agent可以同时支撑 tutor 的准确性和可解释性
3. 可借鉴的核心机制
将知识检索结果作为上下文注入模型回答过程
用多个维度评估agent输出，例如 accuracy、clarity、difficulty alignment、relevance
将 prompt engineering 与 retrieval 结合，提高教育问答质量
4. 对我们项目的启发
我们项目当前的agent还主要依赖模型自身知识，后续如果要增强回答可靠性，可以参考这篇文献，把 RAG 作为知识支撑层。具体来说，可以让agent在回答前先检索教材、定理或知识片段，再把检索结果注入 prompt，从而让 agent 的提示更准确，也更容易解释“为什么这样引导”。
5. 这篇文献支撑的项目设计点
主要支撑：
M3 Knowledge Base / RAG
知识支撑与可追溯性
后续agent与内容生成模块共享 RAG 的可行性

## 2. Learning Content Generation 模块

### 文献 1：MATHWELL: Generating Educational Math Word Problems Using Teacher Annotations（EMNLP 2024 Findings）

**1. 论文核心内容**

这篇文章研究如何用大语言模型自动生成 K-8 阶段的数学应用题，并强调题目要真正“能用于教学”必须同时满足三点：可解（solvable）、答案准确（accurate）、教育适当（appropriate）。作者发现现有公开模型/数据集常常做不到这三点，于是用教师标注构建高质量数据集，微调 Llama-2 (70B) 得到 MATHWELL；专家评估显示其在可解性、准确性、适当性上明显优于公开模型，质量接近 GPT-4。它还借助 Program-of-Thought（让题目附带可执行的解答程序）来保证答案的正确性。

**2. 与我们项目最相关的设计点**

- 出题不是“随便生成”，而要保证可解、答案正确、适合教学
- 生成内容的“答案”必须是可验证的，而不是模型自说自话
- 需要用质量标准（而不仅是流畅度）来评判生成结果

**3. 可借鉴的核心机制**

- 把“可解性 / 答案准确性 / 教育适当性”作为生成的硬性质量标准
- 用 Program-of-Thought / 代码执行让题目自带可验证答案
- 用少量专家标注来校准自动评估

**4. 对我们项目的启发**

我们当前的生成器直接让 LLM 出题，已经出现“答案不正确、选项错误”等问题。可借鉴 MATHWELL，把“答案可由代码/CAS 执行验证”纳入生成流程，并用一小批专家标注来校准我们的自动评分标准。

**5. 这篇文献支撑的项目设计点**

- M3 内容生成器（Content Generator）
- M5 内容验证器（Content Validator，质量标准）

### 文献 2：From Objectives to Questions: A Planning-based Framework for Educational Mathematical Question Generation（EduMath / EQPR，arXiv:2506.00963）

**1. 论文核心内容**

这篇文章针对“生成符合教育目标的数学题”，构建了带多维教育目标标注的 EduMath 数据集（约 16k 题），提出 EQGEVAL 评测（三个评估维度），并提出 EQPR 方法：借鉴教师“计划—评估—优化”的出题过程，把蒙特卡洛树搜索（MCTS）与 LLM 结合，通过 Critic（评估）+ Reflection（反思）两个模块对题目进行迭代优化，使其同时满足多维教育目标。

**2. 与我们项目最相关的设计点**

- 出题要先明确“教什么、达到什么目标”，再生成
- 生成不是一次成型，而是“评估—优化”的迭代过程
- 要用多维教育目标（而非单一题面质量）来指导生成

**3. 可借鉴的核心机制**

- “plan-evaluate-optimize”闭环：先规划教育目标 → 生成 → 评估 → 优化
- Critic + Reflection 双模块：评估并给出明确的修改方向
- 用多维教育目标驱动生成，便于难度与覆盖控制

**4. 对我们项目的启发**

我们可以把出题从“一次性 prompt”升级为“规划 → 生成 → 验证 → 再生成”的迭代闭环（正好与导师建议的“内容验证 + 不通过则重生成”一致），并为每道题显式声明教育目标/知识点，方便后续做难度控制与题库覆盖统计。

**5. 这篇文献支撑的项目设计点**

- M1 知识点组织器（Knowledge Organizer）
- M4 难度控制器（Difficulty Controller）
- M5 内容验证器（迭代优化闭环）

### 文献 3：Multi-Agent Collaborative Framework for Math Problem Generation（EDM 2025）

**1. 论文核心内容**

这篇文章提出一个协作式多智能体框架，把“推理时计算（inference-time computation）”引入自动出题（AQG）：让多个 agent 迭代精修“题目—答案对”，以更好地平衡题目的复杂度与认知需求；并用五个元评估维度——relevance（相关性）、importance（重要性）、clarity（清晰度）、difficulty matching（难度匹配）、answerability（可作答性）——来评估生成质量。初步结果表明多 agent 协作能产出更可控、更有教学价值的内容。

**2. 与我们项目最相关的设计点**

- 难度/复杂度需要被显式控制，而不是碰运气
- 生成质量应有一套明确的评估维度
- 多 agent 分工可提升出题质量

**3. 可借鉴的核心机制**

- 多 agent 分工、迭代精修，而非单次生成
- 五维元评估标准（可直接作为我们的质量指标）
- 用推理时迭代来提升难度可控性

**4. 对我们项目的启发**

这五个评估维度可以直接落成我们的量化指标（见下文 2.1）。短期我们可用“生成 → 验证 → 重生成”来近似这一思路；中期可把生成模块拆成“出题 agent / 验证 agent / 难度 agent”协作。

**5. 这篇文献支撑的项目设计点**

- M3 内容生成器
- M4 难度控制器
- M5 内容验证器
- （未来）多 Agent 协作

### 文献 4：MATH-VF: Step-Wise Formal Verification for LLM-Based Mathematical Problem Solving（arXiv:2505.20869）

**1. 论文核心内容**

这篇文章提出 MATH-VF 框架，用于验证 LLM 数学解答的正确性：Formalizer 把自然语言解答翻译成形式化表示，Critic 集成计算机代数系统（CAS）与 SMT 求解器，对每一步逐句校验；发现错误时给出纠正反馈，并支持“验证 → 反馈 → 再生成”的 refinement。在 MATH500、ProcessBench 等基准上优于已有方法。

**2. 与我们项目最相关的设计点**

- 不能只看最终答案，要逐步校验
- 要借助外部符号工具（CAS/SMT）保证数学正确
- 验证不通过要能反馈并再生成

**3. 可借鉴的核心机制**

- Formalizer + Critic 结构：把题目/解答形式化后交给 CAS/SMT 校验
- 逐步（step-wise）验证，而不仅是最终答案——正好覆盖导师说的“解题步骤连贯性”
- 验证不通过即反馈再生成的闭环

**4. 对我们项目的启发**

这是我们内容验证器的直接蓝本：把生成的题目/解答经“记号归一化”送入 SymPy(CAS) 逐步校验数学正确性与步骤连贯性，失败则反馈重生成；难以符号化的题目降级为数值抽样 / 规则检查。

**5. 这篇文献支撑的项目设计点**

- M5 内容验证器（核心）
- M3 内容生成（验证—再生成闭环）

## 2. Learning Content Generation 模块

### 2.1 生成内容质量

> 逐题评估：客观项由 CAS/规则自动判定，主观项由人工或 LLM 打分。

| 指标名称 | 指标含义 | 评分/计算方式 |
| --- | --- | --- |
| 数学正确性 (Mathematical Correctness) | 题目标注的最终答案在数学上是否正确 | 经记号归一化后用 SymPy/CAS 重新求解，与标注答案化简后相等=1，否则=0；无法符号化的题目改用数值抽样比对 |
| 答案一致性 (Answer Consistency) | 题面、选项、解析、最终答案之间是否相互一致 | 规则检查：单选恰好 1 个正确项、多选正确项≥1 且不为全部、填空 `___` 数等于答案数；全部满足=1，否则=0 |
| 干扰项有效性 (Distractor Validity，仅选择题) | 错误选项是否“看似合理但确实错误” | 每个错误选项经 CAS 判定确为错误的比例；可附加“是否对应常见误区”的人工标注 |
| 解题步骤连贯性 (Solution Step Coherence) | 解题步骤是否逻辑连贯、每步可由上一步推出 | 0-3 分：0=步骤断裂或跳步；1=部分连贯；2=基本连贯；3=每步均可由前一步推出 |
| 可解性 (Solvability) | 题目是否有明确且可判定的答案 | 可解=1；欠定、矛盾或无解=0 |
| 难度匹配度 (Difficulty Match) | 实际难度是否与目标难度（easy/medium/hard）一致 | 以解题步数或 CAS 操作数（或人工/LLM 评级）与目标难度比对，一致=1，否则=0 |
| 格式合规性 (Format Validity) | 公式、括号、`$` 分隔符是否配对，有无截断 | 规则检查通过=1，否则=0 |
| 知识点对齐度 (Topic Alignment) | 题目是否覆盖指定知识点 | 题目标签与目标知识点一致（或经知识库检索确认）=1，否则=0 |
| 清晰度 (Clarity) | 题面表述是否无歧义、易于理解 | 0-3 分（人工或 LLM）：0=有歧义/不可理解；3=表述清晰无歧义 |
| 教学相关性 (Relevance) | 题目对该知识点是否相关且有练习价值 | 0-3 分（人工或 LLM 评分） |

### 2.2 生成与验证过程

> 系统级聚合统计。

| 指标名称 | 指标含义 | 评分/计算方式 |
| --- | --- | --- |
| 一次通过率 (First-pass Validation Rate) | 首次生成即通过全部验证的题目比例 | 首次通过题数 / 总生成尝试数 |
| 平均重生成次数 (Average Regeneration Count) | 一道题通过验证平均需要的重试次数 | 总重试次数 / 最终通过题数 |
| 最终产出率 (Yield Rate) | 最终可用（通过验证）题目占全部尝试的比例 | 通过题数 / 总尝试数（含重试） |
| 各检查失败分布 (Failure Breakdown) | 各验证检查项的失败占比，用于定位薄弱环节 | 单项检查失败次数 / 总失败次数 |
| 填空数量不匹配率 (Blank–Answer Mismatch Rate) | 填空 `___` 数与答案数不一致的比例（导师指出的问题） | 不匹配题数 / 填空题总数（目标值趋近 0） |
| 选项正确性错误率 (Option Correctness Error Rate) | 选择题标注的正确项实际为错误的比例 | 标注错误题数 / 选择题总数 |
| 生成延迟 (Generation Latency) | 平均每题生成（含验证）耗时 | 总耗时 / 题目数 |
| 人工–自动评估一致性 (Human–Auto Agreement) | 自动评分与人工评分的吻合程度，用于检验自动验证是否可信 | 两者一致的题数 / 抽检题数（或相关系数） |
| 题库覆盖度 (Coverage) | 知识点 × 题型 × 难度 各组合的覆盖情况 | 已覆盖组合数 / 目标组合总数 |
