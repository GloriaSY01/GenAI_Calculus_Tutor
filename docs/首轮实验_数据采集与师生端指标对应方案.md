# 首轮实验：数据采集与新教师端指标对应方案

版本：v2，2026-11-07。

依据：提交 `82e1560` 的后端，加当前工作区尚未提交的教师端精简改动。新界面以 `student-frontend/src/pages/teacher/LegacyDashboard.jsx` 为准，设计说明见 [教师端分层精简说明](教师端_分层精简说明.md)。

状态更新（2026-11-08）：核心链路已开始落地，详见 [数据链路运行与验收](数据链路_运行与验收.md)。新工作区已接入题次快照、不可变提交、AI 展示确认和独立实验范围的教师统计。下文保留 v2 设计及改造前基线，用于核对尚未实施的部分；不应将所有拟议字段理解为已实现，也未连接部署数据库核查真实样本。

当前实现与基线的主要差异：

- “参与学生”已改为提交者与提问者的去重并集，去除旧估算口径。
- AI 状态按提交时刻固定为 none / received / unknown，未知组在详情中单列。
- 新教师端与教学助手均读取 `scope=learning`，按实验、班级隔离，旧日志不混入。
- 数据存储目前采用两张 v2 SQL 表及 JSON 实体快照，并非下文规划的完整拆表结构。
- 完整实验身份、权限、退出、研究导出、跨设备草稿同步等仍待后续实施。

## 1. 设计原则：界面精简，记录可复核

教师需要先回答“这个班有多少人在使用、练习表现如何、哪些知识点需要讲评”。新界面保留三个概览指标和一组知识点表现；更多量化指标按需展开。

研究需要的首次作答、重试、求助顺序、中途退出等仍然记录，但不全部展示在教师首页。

本方案按三层组织：

1. **教师首页**：参与学生、练习提交、提交正确率、知识点表现。
2. **展开的量化详情**：按难度和辅助状态统计的提交正确率、样本数、导师推理分布。
3. **研究与质量导出**：首次正确率、重试、题次最终结果、流程完成、错误与缺失记录。独立于日常教师首页。

首轮默认目标为验证使用过程、采集完整性和看板一致性。若要验证学习提升，另设计前后测和对照，不把练习正确率直接当学习增益。

## 2. 新教师端已经实现什么

### 2.1 首页

- “参与学生（估算）”：读取 `n_students`，保留估算提示。
- “练习提交”：读取 `practice_submission_count`。
- “提交正确率”：读取 `practice.correct_rate`，同时显示答对/已判分次数。
- “知识点表现”：读取 `practice.practice_by_topic`，显示正确率及 `correct / attempts`，默认五项，其余展开。
- 知识点排序：至少五次提交的排在前面，再按正确率升序、提交次数降序和名称排序；少于五次的显示“样本少”。五次只是展示规则，不代表统计显著性。
- 点击知识点可为教学助手设置上下文。

首页知识点已改用练习判分数据，不再使用导师会话中的 `by_topic.solve_rate`。两者不能互换。

### 2.2 更多量化指标

- 全部难度与各难度下的“未标记辅助”“标记为 AI 辅助”提交正确率。
- 每个比例旁显示该组提交次数；无提交显示“—”。
- 有导师对话数据时展示五级推理分布，标注模型评估。

### 2.3 练习配置和教学助手

练习配置默认折叠，保留题型、难度、题量、模板、创建和删除。当前仍是配置保存，未实现学生接收任务和作业完成率。

教学助手继续保留，切换班级清空聊天历史。它的服务端事实输入仍主要来自旧会话指标，尚未与新首页完全对齐。

### 2.4 已删除与尚未解决

界面已经移除重复摘要、学习态度/gaming 判断、研究条件视图和无数据示例图。这些不再作为待办界面删除项。

但后端仍计算旧指标，教师助手仍可能引用它们。删除卡片不等于消除了数据口径问题。

当前页面展示选定班级全部已记录数据，没有实验或日期筛选；“五次提交”也不等于五名学生。班级选择是筛选功能，不是访问授权。

## 3. 师生端已有链路与主要缺口

### 3.1 现有链路

- 练习提交 → `POST /grade` → `generator.grade` → `practice_grade` → `analytics._compute_practice` → 新首页和详情。
- 浮动学习 Agent → `/session/start`、`/session/{id}/message` → `session_start`、`turn` → 推理分布。
- 教师查看 → `GET /analytics/class?class_id=...` → `ClassAnalytics`。
- 教师提问 → `POST /analytics/ask` → `_facts_block` 和 `teacher_prompt`。

数据库模式读取数据库事件；未配置数据库时读取本地 JSONL，不自动合并两种来源。无数据库时，学生进度主要保存在浏览器；有数据库时 `student_progress` 也是可覆盖快照。

### 3.2 必须修正的数据问题

1. **人数估算**：`compute` 取练习人数和对话人数的较大值，未做集合并集；`anon` 不可区分参与者。新界面只是如实标注估算，并未修正公式。
2. **缺提交标识及原始答案**：`practice_grade` 记录正确性等，但不保存本次答案，也没有幂等的 `attempt_id`。网络重发可能重复记数。
3. **尝试计数不稳定**：`generator.grade` 递增进程内题目记录的 `attempts`，不按参与者题次隔离，也不将递增值持久化。
4. **AI 分类缺少先后关系**：当前匹配整段数据中同学生、班级、题目的导师会话，可能把答后求助归入此前提交。浮动 Agent 不回写题目的 `assisted`；文件中未挂载的 `QuestionHelp` 不能当作当前第二个有效入口。
5. **回复成功不等于正常帮助**：有前端演示回退和服务端兜底；HTTP 成功不证明浏览器展示了正常题目帮助。
6. **模式与流程缺失**：自由练习和挑战共用判分接口，事件无题次/挑战/实验 ID，未答、跳过、退出不完整。
7. **题目档案限制**：判分使用进程内注册表，数据库启动加载默认最近 2,000 条；本地文件也裁剪最近记录。长期实验不能只依赖这一缓存。
8. **实验隔离和授权缺失**：统计没有实验批次筛选和可靠的演示过滤；本地日志目录中的模拟日志可能被聚合。客户端角色切换与班级参数不能替代服务端授权。
9. **挑战不等于无 AI 测验**：交卷前仍挂载能拿到当前题目的浮动 Agent；交卷逐题判分，批改中断可能已有部分记录，没有服务端整卷提交。
10. **判分结果不是数学真值保证**：例如填空主要做归一化字符串匹配。保留题面、答案和评分版本，支持人工复核，不将判错直接等同于概念错误。

## 4. 教师指标的数据契约

本节区分“当前字段”和“实验目标口径”。后续调整分母或过滤条件必须升级 `metric_version`，不能悄悄改变同名指标的含义。

### 4.1 T1 参与学生：首页

**教师问题**：当前范围里实际有多少学生参与练习或辅导？

- 当前字段：`n_students`，按现有算法估算。
- 目标公式：选定范围内存在有效提交或成功记录的学生导师请求的去重 `participant_id` 并集。
- 只打开页面或点击开始不计入该数；研究中的“开始实验人数”另算。
- 同一学生多题、多轮对话只算一人。教师聊天不进入学生人数。
- 必需记录：稳定参与者 ID、班级、实验、run、提交/请求事件及状态。
- 实施前继续显示“估算”；身份和并集统计验收后才改为“参与学生”，不能称为全班人数或参与率。
- 没有正式班级花名册，不计算“参与人数 / 全班人数”。

### 4.2 T2 练习提交：首页

**教师问题**：班级产生了多少次可评分的作答？

- 当前字段：`practice_submission_count = practice.n_answers`，来自每条 `practice_grade`。
- 目标公式：评分状态成功的去重 `attempt_id` 数。
- 单位为次，包含真实重试；网络重发、同一答案的继续判分不增加次数。
- pending/error 不计入已判分提交，不记为答错；质量导出单列。
- 包含的自由练习/挑战模式必须随统计范围明确；前后测若加入实验，不默认混入练习统计。
- 必需记录：attempt、题次、提交时间、判分状态、模式。
- 不将该指标改名为“完成题数”或“完成率”。

### 4.3 T3 提交正确率：首页

**教师问题**：已判分提交中，答对的比例是多少？

- 当前字段：`practice.correct_rate`；界面答对次数取总提交减 `not_correct_count`。
- 目标公式：去重成功判分中 `correct=true` 的次数 / T2。
- 展示比例和“答对 C 次 / 已判分 N 次”；N=0 显示“—”。
- 首次与重试均计入，按题型不额外加权；这是提交层表现，不是独立能力、首次正确率或学习增益。
- 后端建议显式返回正确数，避免客户端用缺省的错误数反推；缺失字段不能被解释为全部答对。

### 4.4 T4 知识点表现：首页

**教师问题**：哪些知识点的练习表现需要关注？

- 当前字段：`practice.practice_by_topic[].topic / correct / attempts / correct_rate`。
- 目标公式：按稳定 `section_id` 分组，每组复用 T2、T3。
- 继续保留默认五项及小样本提示，不恢复第二套会话知识点图。
- 新采集保证每个题次有主知识点 ID；未能归属的旧记录保留“未归属”，不得静默删除后再宣称分项与总量一致。
- 当前界面过滤无提交项和 `General / Free chat`，不代表后端已经完成归属检查。
- 排序阈值是教学浏览辅助，不自动判断“薄弱学生”或“未掌握”。同一人反复提交可形成五次，研究导出另保留去重人数。
- 点击知识点传给助手的上下文应逐步从展示名称改为 ID；中英文名称不能分裂成两个知识点。

### 4.5 T5 难度 × AI 辅助状态：展开详情

**教师问题**：不同难度和帮助使用情况下的提交表现如何？

- 当前总比例：`independent_solve_rate / ai_assisted_solve_rate`。
- 当前总分母：`practice.practice_completion_modes[].count`。
- 当前难度分组：`practice.by_difficulty_completion` 中的 `independent_rate / ai_assisted_rate` 和对应 `*_submissions`。
- 目标公式：每个难度、帮助状态组内正确的已判分提交数 / 该组全部已判分提交数。
- 同时保留“全部难度”行、比例和提交数；未知难度独立分组，不填为 medium。
- 现阶段继续使用“未标记辅助 / 标记为 AI 辅助”名称与时间顺序限制说明。
- 完成新采集后，帮助状态为 `none / received / unknown`。未知必须有可见数量或单独行，不能默认为未辅助；各组分母之和必须等于 T2。
- 未辅助仅指本系统该题没有已观测帮助，不代表没用外部 AI、没阅读教材或没有之前的概念帮助。
- 不将两个比例之差解释为 AI 效果：难度、学生基础和自选择求助均可能不同。
- 已正常展示但后来被人工发现内容错误的回复仍属于“收到帮助”，另标质量问题，不能为改善结果而剔出辅助组。

### 4.6 T6 导师推理分布：展开详情

**教师问题**：学生在导师交互中呈现了怎样的解释？

- 当前字段：`reasoning_distribution`，五级 `none/weak/partial/adequate/strong`，当前按记录的对话轮次计数。
- 当前所有记录轮次可能包含兜底或拦截；不应将其评级直接等同学生能力。
- 目标公式：等级 k 的可评估学生轮次数 / 全部可评估学生轮次数。
- “可评估”需有明确规则和 `assessment_status`，服务失败、拦截、缺评分单列；不能把无法评估自动填为 none。
- 正常轮次中 none 的含义由量表规定，不因分数低而排除；概念提问与解释任务的差异在研究中另标。
- 保留推理分布和参考提示，不新增首页平均推理分、mastery 或态度评分。
- 规则改变前后用不同 rubric/metric 版本，不能直接比较分布。界面未来应显示可评估轮数及未评估数。

## 5. 首页之外仍需记录的研究指标

这些指标用于研究导出，不增加首页卡片。各指标都附过滤范围、分子分母、缺失量和参与人数。人均汇总与题次加权分别命名，不能混用。

### R1 开始与完成

- 开始人数：有 `run_started` 的去重参与者数；不等于 T1。
- 流程完成率：已完成 run / 已开始 run，按固定截止时间报告进行中、中断、退出。
- 重复参加需预先规定纳入规则，不能把多次 run 当成多个人。

### R2 作答与判分覆盖

- 作答覆盖率：至少一次有效提交的题次 / 实际展示题次。
- 判分覆盖率：至少一次成功判分的题次 / 实际展示题次。
- 未展示、展示未答、已答待判分和技术失败分别报告。

### R3 首次正确率

- 首次 `attempt_no=1` 成功判对的题次 / 首次已有明确判分的题次。
- 首次失败后继续判分沿用原 ID；若第二次先判对，不得拿第二次替代缺失的首次。
- 可按首次帮助状态分层；unknown 不并入无帮助组。

### R4 重试与最终结果

- 重试率：至少两次有效提交的题次 / 至少一次有效提交的题次，判分失败不抹去提交行为。
- 最终正确率：已结束或截止的已提交题次中至少一次判对的题次 / 最终可判定的已提交题次。
- 至少一次判对即为可判定正确；其余须所有提交均有明确判分且都错才判定最终错误；无法判定的单列。
- 未答题不进入上述正确率分母，但必须在 R2 和整卷结果中保留。

### R5 求助过程

- 首次提交前帮助使用率：首次提交状态为 received 的题次 / 首次帮助状态明确的题次。
- 求助后修正率：首次判错、尚未答对时收到帮助，随后第一次重提判对的题次 / 满足该顺序且这次重提已有明确结果的题次。
- 求助后未再提交、重提未判定均单列。该比例是描述性关联，不是因果效果。

### R6 技术质量与可选耗时

- 按生成、判分、导师分别统计最终失败的逻辑请求 / 已确定结果的逻辑请求，pending/unknown 单列。
- 网络重发沿用逻辑 ID，传输层失败可另外记录。
- P0 保存展示、提交、服务器处理时间，但“展示到提交时长”不能称思考时间。
- P1 才考虑页面可见/活跃计时与闲置阈值，报告采集完整度。已有 `elapsed_ms` 从生成开始，`latency_ms` 是服务端处理耗时，均不能代替有效解题时间。

## 6. 最小事件与数据实体

不要求首轮收集逐键输入、所有点击或完整浏览轨迹。原始记录足够支撑 T1–T6，并允许还原一次做题过程即可。

### 6.1 统一标识

- `experiment_id: UUID`：实验批次和协议。
- `participant_id: UUID`：稳定的假名化参与者；不使用真实姓名。
- `run_id: UUID`：一次实验过程，断线恢复沿用。
- `exposure_id: UUID`：一次题目作答机会，分配时创建，首次实际展示另记；返回同一题沿用，重新练习另建。
- `attempt_id: UUID`：一次明确提交，幂等键。
- `session_id: string`：兼容现有导师会话字符串 ID；关联 run，题目级关联 exposure。
- `request_id / reply_id: UUID`：新导师请求及回复标识，支持顺序和展示确认。
- `question_id: string`、`section_id: string`：兼容已有题目及教材 ID。
- `assignment_id: string/null`：兼容已有作业 ID；首轮不接作业时为空。

同一参与者、班级、实验范围由服务端验证。跨题、跨班或其他人的 ID 不能仅凭客户端参数建立关联。

### 6.2 公共事件外壳

新增事件至少包含：

- `event_id: UUID unique`、`schema_version: integer`、`event_type: string`。
- experiment、participant、run、class 标识；按事件附 exposure、attempt、session、request 标识。
- `occurred_at: timestamptz/null`：来源方发生时间；`received_at: timestamptz`：服务端接收时间。
- `client_seq: integer/null`、`client_instance_id: string/null`：同一客户端会话的顺序；多标签页不可混用序列。
- `source: string`、`is_demo: boolean`、`app_version: string`、`payload: JSON/JSONB`。

标识并非所有事件都必填，例如生成失败可尚无 question ID。必填规则由事件 schema 定义，不能用虚构 ID 补齐。

### 6.3 最小事件清单与触发时机

1. **run_started / run_completed / run_interrupted / run_exited**：实验流程开始、完成或明确状态变化。记录协议版本、起止时间、原因。关闭页面事件不可靠，缺少结束不能自动当主动退出。
2. **question_assigned / question_presented**：分配与首次实际展示分开。记录题次、题目版本、知识点、模式、难度、题型、来源和语言；预加载不算展示。
3. **answer_submitted**：服务端接受明确提交后记录答案、attempt_no、帮助状态和已展示回复 ID。
4. **answer_graded / answer_grade_failed**：关联原 attempt，保存结果或失败原因。重试评分不新建作答尝试。
5. **tutor_requested / tutor_responded / tutor_response_presented**：区分学生请求、服务端产生回复、客户端实际展示。记录请求输入、回复、状态、推理评估、模型/提示词/评分量表版本。
6. **request_failed**：逻辑请求失败，记录阶段、错误码和可恢复状态；不伪造学生错误或推理评级。
7. **assessment_submitted / assessment_graded**：仅当首轮包含挑战时需要；锁定整卷题单和答案，再完成逐题判分。未答题保留。

生成成功可复用 `question_generated`，补充请求和实验关联；生成失败另记，不因没有题目而丢失。收藏已有事件，可保留，但不是首轮成效指标。

### 6.4 参与者和 run

参与者记录稳定编码；参与者与实验登记关系保存 `consent_version`、`consented_at`、退出状态。run 保存 class、protocol_version、app_version、started_at、ended_at/null、status、end_reason。

登记信息独立于 run，同一人再次参加不会再次创造身份。研究者如需身份映射，独立保存并限制访问。

### 6.5 题次及不可变题目快照

exposure 保存 run、question、section、mode、assigned_at、presented_at/null、closed_at/null、status，可选 assessment/assignment ID。

快照保存：

- 学生当时的题干、选项顺序、题型、语言及显示内容版本；翻译与源题不同则保留翻译版本或快照引用。
- 来源、难度标签、生成/核验版本。
- 服务端正确答案、评分材料与 grader_version，不能随未作答题公开返回。

现有生成题表可以复用，但实验题目应保留到协议规定的保存期限，不能只靠最近 2,000 条缓存恢复。难度标签是系统标签，不代表已校准的实测难度。

### 6.6 作答尝试

必需字段：

- attempt_id、exposure_id、`attempt_no: integer`。
- `answer_payload: JSON`：单选索引、多选索引、填空或排序内容。
- submitted_at、graded_at/null、`grade_status: pending/succeeded/failed`。
- `correct: boolean/null`、grader_version、error_code/null。
- `assistance_before_submit: none/received/unknown`、关联的回复 ID。
- `feedback_presented_before: yes/no/unknown`：与 AI 帮助分开；未采集反馈展示时填写 unknown。

唯一约束为 attempt_id 及 (exposure_id, attempt_no)。同 ID 重发须核对身份、题次和答案；答案不同则拒绝，不能覆盖。主动再次提交即新尝试，即使答案相同；继续评分沿用原尝试。

### 6.7 导师记录

正常学生问题和客户端拼接的已提交答案上下文分字段保存，避免把自动附加内容当作学生新写的解释证据。

记录 request/reply/session/exposure、实际输入与上下文、回复内容、response_status、呈现时间、reasoning_assessment、assessment_status、模型/提示词/rubric 版本、处理耗时。

开场白和普通导师回复可分别标记 reply_kind；开场白是否包含可计入的题目帮助由协议规定，不能仅凭创建 session 就计入。服务端兜底、前端演示回复和正常帮助必须可区分。

## 7. AI 辅助分类的时间规则

1. 请求帮助本身不等于收到帮助。
2. 提交时，客户端带上已展示的同题正常回复 ID；服务端验证该回复属于当前参与者和题次。
3. 根据客户端实例顺序、展示确认和服务端时间确定 none、received 或 unknown。缺少确认不能简单判断 none。
4. 冻结每次提交的观察状态；答后求助不追溯修改以前的提交。
5. 迟到的展示确认若能证明发生在提交前，只能作为有审计记录的新计算版本修正；不能覆盖原始事实或无记录改数。
6. 无题目关联的概念问答记录在 run/section 层，不强行分配给所有题。协议需说明这类帮助不在“题目级辅助”分类中。
7. 现有浮动 Agent 为主要采集入口；将来启用其他入口时复用同一协议。

例：同题第一次无帮助答错 → 收到帮助 → 第二次答对。首页贡献两次提交、一次正确，提交正确率 50%；首次正确率贡献 0/1；无帮助组贡献 0/1，辅助组贡献 1/1；重试率与最终正确率各贡献 1/1。

这正是首页提交正确率与研究首次正确率不能混用的原因。

## 8. 后端聚合、教师接口与教学助手

### 8.1 统计范围

建议新增明确的 scope：experiment_id、class_id、观察窗口、纳入的练习模式、截止时间和 metric_version。

新教师端目前没有这些选择器。首轮可以由研究者在后端绑定固定实验范围，界面只增加简短范围说明；若提供切换，则整页、详情和助手一起切换。不能让首页查全部历史、助手查另一批实验。

### 8.2 数据一致性规则

- 同一 scope 下 T2 = 正确提交数 + 错误提交数。
- 所有知识点提交数（包括未归属）之和 = T2。
- 各帮助状态提交数（包括 unknown）之和 = T2。
- 各难度分组之和 = T2。
- 分母为零返回空值；字段缺失/查询失败显示不可用，不回退真实样式的示例值。
- 前端只负责格式化和排序，分子分母由服务端返回，避免多处各算一套。
- 用事务或可靠补偿保证提交、判分结果与事件一致。

旧字段如 independent_solve_rate 可短期保留兼容映射，但新增的 scope、计数、未知量和质量说明应有 schema。迁移期不能把旧记录缺失信息填成新协议默认值。

### 8.3 教学助手必须同步调整

当前 `_facts_block` 仍提供会话 solve_rate、gaming_rate 和旧 by_topic；中文规则回退还把会话 solve_rate 称作整体正确率。这与新首页含义不一致，是本轮数据实施的 P0。

目标事实输入只包含新看板同范围的 T1–T6、知识点、分子分母、缺失和版本。未展开详情不影响服务端解释指标，但不把已移除的态度结论重新带回聊天。

通用分析可以看到当前班级练习汇总；知识点提问引用该知识点的练习数据。样本少时明确有限证据，不编造个人情况、作业完成率或学习效果。

## 9. 首轮实验流程与范围

建议默认采用：

1. 研究者建立独立实验范围，安排班级和匿名参与码，核验题目。
2. 参与者同意后开始 run。
3. 进入指定小节，实际展示题目，提交、重试及按需使用导师。
4. 可选章节挑战；完成后记录结果和结束状态。
5. 教师按班级查看精简看板；研究者导出去标识化事件和派生结果。
6. 抽样人工复核题面、判分与推理评价。

首轮无需同时实现完整作业分发、前后测、细粒度阅读轨迹和能力模型。若研究问题必须使用其中某项，它才成为该实验的前置条件。

当前挑战是学习自检；要作为无 AI 测量，必须限制前端入口并由后端验证阶段权限，还需确定离开挑战去学习的规则，不能只靠提示文字。

## 10. 中断、缺失、隐私与边界

- 统一假名化身份，禁止所有匿名参与者共用 anon；跨设备通过受控参与码恢复。
- 教师默认只看班级汇总；研究者按授权查看原始答案和对话。现有前端角色切换不提供该权限隔离，需要服务端落实。
- 实验前明确保存期限、退出/删除流程和访问范围；身份映射独立保存。
- 不默认采集真实姓名、学号、IP、设备指纹和逐键输入。对话可能含个人信息，导出需脱敏。
- 网络断开先标中断，允许续接；截止后报告未完成，不猜测退出动机。
- 首次缺失、帮助未知、未展示、未答、技术失败均保留各自状态，不统一写零或答错。
- 旧数据按 legacy 单独汇总；缺 attempt、展示或顺序时不能可靠回填新口径。
- 从教师界面删除 gaming/mastery 不等于禁止保留诊断原始数据，但这些值不作为首轮成效结论。
- 当前 explain/control 采用同一教学策略，遗留字段不能构成实验对照组。
- 动态题目、基础能力和自选择求助会影响指标；同一个人多次提交也不是独立样本。研究推断需另设分析方案。

## 11. 数据结构如何落地

复用现有 generated_questions、tutor_sessions 和 learning_events，并增加参与者登记、run、exposure、attempt；含挑战则增加 assessment 或等价的不可变整卷记录。

事件保留审计事实，attempt/exposure 作为查询和约束模型。明确哪份是权威记录，避免事件与业务表独立更新后互相矛盾。student_progress 继续用于恢复界面，不承担研究历史存储。

现有库使用字符串 ID、Float 时间和 JSON。本文的新 UUID/timestamptz/JSONB 是建议类型，不要求一次性替换全部旧表；新协议可逐步扩展，数据库兼容性需明确。既有表增加字段和约束需要迁移，不能只依靠 metadata.create_all()。

重启恢复要验证实际题目按 ID 可读、已有 attempt 不重算成新提交、导师及进度关联不丢失。

## 12. 实施顺序

### P0：让新看板的数据可信

1. 明确实验范围、授权、参与码、协议及真实/演示隔离。
2. 统一 run/exposure/attempt；保存原始答案和幂等记录。
3. 实际展示与导师回复呈现事件；按提交时间冻结帮助状态。
4. 修正 T1 并集、T2 去重、T3/T4 分子分母及 T5 unknown。
5. T6 保存评估状态与版本，显式区分无法评估；完成规则说明和小样本人工核对。
6. 同步教学助手事实输入和回退文案，禁止继续把会话解出率称为首页正确率。
7. 接入新范围和质量字段、研究导出、备份及验收；保持三张首页卡片和按需展开结构。
8. 首轮包含挑战时，完成锁卷、未答记录和中断续判；包含无 AI 测验时再落实阶段限制。

### P1：按研究问题增加

活跃时间、阅读路径、更多错误类型标注、完整作业分发、推理量表扩大复核。不要为了这些字段再次扩张教师首页。

### P2：学习效果研究

校准题目难度、等价前后测、延迟测验及对照设计。若首轮即研究效果，应在招募前完成对应设计，而不是收完数据后补做。

## 13. 验收清单

使用独立测试实验，不写真实参与记录。每个指标可追溯原始 ID、scope、分子、分母和版本。

1. 一人既练习又对话，T1 只计一人；只有对话的人与只有练习的人正确并集。
2. 同 attempt 网络重发只计一次；主动再次提交计新一次。
3. 先错后对：首页两次、50%；首次 0%；最终题次正确。
4. 首次待判分、第二次正确：首次保留缺失，不被第二次替代。
5. 答后求助：之前提交不变；正常帮助展示后提交进入辅助组；未知展示状态进入 unknown。
6. 正常回复、服务端兜底、前端演示、请求失败可区分；展示不重复计对话轮次。
7. 多知识点、难度和辅助分组计数均与总量一致，包括未知与未归属。
8. 五次阈值与默认五项符合新界面；剩余项可展开；小样本不自动称为未掌握。
9. 空班、只有对话的班、零正确但有提交的班分别正确呈现：无分母为“—”，真实零正确为 0%。
10. 班级切换与实验范围切换同时影响首页、详情和助手；越权请求被拒绝。
11. 助手引用的练习正确率、样本数与卡片一致，不引用旧会话解出率冒充。
12. 服务重启后题目和尝试可恢复；超出最近缓存的实验题仍可复核。
13. 含挑战时保留未展示/未答，整卷批改恢复不重复提交；无 AI 测验无法通过直接导师请求绕过限制。
14. 导出可重复生成且记录版本；模拟/legacy/未同意数据不混入新实验主结果。

## 14. 首轮前需要确认

- 研究目标：可用性与过程观察，还是学习效果。
- 参与者范围、班级、固定题组/动态题、章节、题型和时长。
- 是否包含挑战、是否要求无 AI、是否允许外部帮助。
- 数据保存期限、同意流程、查看与导出权限。
- 实验截止时间、迟到数据处理、重复参加和缺失规则。
- 推理评分的可评估范围、量表版本和人工复核方法。

确认后固定 experiment/protocol/metric 版本再采集。新教师界面可以保持简洁，数据记录仍应完整；二者不需要有相同数量的指标。
