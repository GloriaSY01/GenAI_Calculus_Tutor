# 教师界面 · 功能文档（Teacher Dashboard）

对应文件：`frontend/teacher_app.py`（**独立 Streamlit 应用**，自己的根 URL / 端口）
共享模块：`frontend/api.py`、`frontend/ui.py`、`frontend/i18n.py`
后端支撑：`backend/analytics.py`、`backend/assignments.py`
演示数据：`scripts/seed_demo_logs.py`

本次为**全新**教师界面，对应评审 Jon 的反馈：
1. 以**班级级别**（而非个人）呈现数据；
2. **不只展示描述性统计**，而是给出可解释的洞察 + 可用自然语言追问的助手；
3. **简化图表**；
4. 教师核心诉求：**数据分析 + 布题**。

### 进入方式（学生端 / 教师端已彻底分开）

学生端与教师端是**两个独立的 Streamlit 应用**，各自运行在自己的根 URL / 端口上，
不再使用 Streamlit 多页面路由（`pages/`）。这样做的原因：多页面路由在预览代理 /
iframe 环境下切换到 `/Teacher_Dashboard` 时 websocket 容易握手失败（`status 0`）；
拆成两个根 URL 后彻底规避该问题。

```bash
# 先启动后端
uvicorn backend.main:app --port 8000

# 学生端
streamlit run frontend/streamlit_app.py --server.port 8501   # http://localhost:8501

# 教师端（独立）
streamlit run frontend/teacher_app.py  --server.port 8502   # http://localhost:8502
```

## 2. 顶部 KPI（班级级）

一屏看懂全班状态，全部为**聚合指标**，不指向任何个人：

| 指标 | 含义 | 来源字段 |
|---|---|---|
| 活跃学生 | 有练习记录的学生数 | `n_students` |
| 会话数 | 助教会话总数 | `n_sessions` |
| 解题率 | 会话中最终解出的比例 | `solve_rate` |
| 平均推理质量 | 0–4 分（none→strong） | `avg_reasoning` |
| 平均掌握度 | 0–100 | `avg_final_mastery` |
| 平均每会话轮数 | 对话轮数均值 | `avg_turns_per_session` |
| 刷量/应付信号 | 疑似 gaming 会话占比（悬停有解释） | `gaming_rate` |
| 护栏拦截率 | 索要答案/注入被拦截的回合占比 | `guardrail_rate` |

数据来自 `GET /analytics/class`。

## 3. 左栏：简化图表

遵循“图表简化、按班级”的原则，只放最能指导教学决策的少量图：

| 图表 | 说明 | 教学用途 |
|---|---|---|
| 各知识点**解题率**柱状图 | 主色蓝，越低越需要补 | 一眼看出班级最薄弱的知识点 |
| 各知识点**平均推理质量**柱状图 | 琥珀色，0–4 | 区分“会做但不会解释”的知识点 |
| 全班**推理质量分布**柱状图 | none→strong 各等级占比 | 左侧偏高说明学生只写步骤不解释 |
| 完整表格（可展开） | 每个知识点的 attempts / 解题率 / 推理 / 掌握 / gaming | 需要细看时展开 |

图表在无数据时显示友好空状态提示。

**知识点归属（topic 解析）**：`backend/analytics.py` 把每个会话归到某个知识点的规则是：
若 `session_start` 事件带显式 `topic` 字段则优先使用它（演示 / 模拟数据用此方式覆盖全部
7 个知识点）；否则回退到 `problem_id → topic` 映射（真实练习会话走这条路径）。这样真实
数据与模拟数据可以共存、互不影响。

## 4. 右栏：洞察 + 助手（“不只是描述性统计”）

### 4.1 Insights 洞察卡片（规则自动生成）
后端 `backend/analytics.build_insights` 把聚合数字转成**结论式**卡片，按严重程度标注：

- 🟢 info · 🟠 warning · 🔴 critical

覆盖的洞察类型：
| 类型 | 触发逻辑（示例） | 卡片内容 |
|---|---|---|
| 最薄弱知识点 | 解题率最低且 < 60% | “班级在 X 最吃力，解题率 40%、推理 1.2/4，建议复习或布置更简单练习” |
| gaming 行为 | 疑似 gaming 会话占比高 | 提示可能存在应付/糊弄行为 |
| 参与度/推理 | 平均推理过低或很高 | 低则建议鼓励“为什么/如何”解释；高则正向反馈 |
| 数据覆盖 | 会话样本过少 | 提示数据不足、趋势待积累 |

### 4.2 Ask about your class 自然语言助手
- 教师用**自然语言**提问（提供 3 个示例问题，或自行输入）
- 调用 `POST /analytics/ask`：后端把**班级事实块**喂给 LLM，要求“只依据事实、给 2–4 句可执行建议”
- **健壮性**：LLM 不可用时自动回退为规则总结（指出最薄弱知识点 + 总体解题率/推理），保证不崩

## 5. Gaming（应付/糊弄）检测说明

在 `backend/analytics.py` 用轻量、可解释的启发式，在**会话级**判定是否疑似 gaming：

- 命中护栏（“直接给我答案” / prompt injection）；或
- 会话内“极快回合（`latency_ms < 1500`）+ 空/极短解释（词数 ≤ 2）”占比 ≥ 60%

判定阈值对教师**透明**（写在洞察说明里），用于教学决策而非给个人定性。这也呼应评审建议中“探索学生 gaming 行为”的研究方向。

## 6. 布题（Assign practice）

教师可基于上方数据洞察，直接为班级创建练习任务。

### 6.1 创建表单（左）
| 字段 | 说明 |
|---|---|
| 任务标题 | 必填，如“极限复习——0/0 型” |
| 知识点 | 下拉选择（`/topics`） |
| 题型 | 单选/多选/填空/排序 |
| 难度 | easy / medium / hard |
| 题目数 | 1–20 |
| 给学生的说明 | 可选备注 |

提交调用 `POST /assignments`，持久化到 `data/assignments.json`。

### 6.2 任务列表（右）
- 列出所有已布置任务（标题、知识点/题型/难度/题数、备注）
- 每条可 `删除`（`DELETE /assignments/{id}`）
- 数据来自 `GET /assignments`

## 7. 演示 / 模拟数据（Seed demo data）

真实日志在早期只有极少会话时，图表会近乎空白、不便演示。为此提供了一个种子脚本，
生成**贴近真实的模拟会话日志**，让 KPI、按知识点柱状图、推理质量分布和洞察卡片一次填满。

脚本：`scripts/seed_demo_logs.py`

```bash
python3 scripts/seed_demo_logs.py    # 生成后刷新教师端即可看到
```

特点：

| 方面 | 说明 |
|---|---|
| 数据规模 | ~45 条会话、12 名学生、覆盖学习路径全部 **7 个知识点** |
| 真实梯度 | 各知识点有不同画像：越靠后/越难的 topic 解题率更低、推理更弱、gaming 更多 |
| 行为覆盖 | 含 gaming/guardrail 行为（急促作答、空回复、“直接给我答案”），驱动对应 KPI 与洞察 |
| 写入格式 | 与 `store.py` 完全一致的 `session_start` + `turn` 事件（`session_start` 额外带 `topic`） |
| 幂等 | 文件统一用 `sim_` 前缀；重跑先清除旧的 `sim_*.jsonl`，**绝不触碰真实会话日志** |
| 可复现 | 固定随机种子（`SEED=42`），每次生成结果一致 |

> 说明：模拟数据仅用于界面演示与联调。正式实验统计时可删除 `data/logs/sim_*.jsonl`，
> 教师端会自动只反映真实会话。

## 8. 依赖的后端接口

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/topics` | 知识点列表（布题用） |
| `GET` | `/analytics/class` | 班级级聚合统计 + 洞察 |
| `POST` | `/analytics/ask` | 基于班级数据的自然语言问答 |
| `GET` | `/assignments` | 列出布置的练习 |
| `POST` | `/assignments` | 新建布置 |
| `DELETE` | `/assignments/{id}` | 删除布置 |

后端模型见 `backend/schemas.py`：`ClassAnalytics`、`TopicStat`、`AnalyticsInsight`、`AnalyticsQuery/Answer`、`AssignmentCreate/Assignment`。

---

## 9. 隐私与数据边界

- 教师端所有指标均为**班级聚合**；`ClassAnalytics` 不返回单个学生的会话明细或姓名。
- gaming/参与度以**占比**呈现，用于教学决策，不对个人定性。
- 原始 per-session 日志仅保留在 `data/logs/` 供研究分析（`scripts/analyze_logs.py`），不在教师界面暴露到个人粒度。
- 演示用的 `sim_*.jsonl` 为**合成数据**（虚构的 `stu_xx`），不含任何真实学生信息；用于统计前应删除。
