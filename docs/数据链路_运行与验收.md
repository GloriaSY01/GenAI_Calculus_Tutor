# 学生端—数据库—教师端：首轮实现

更新：2026-11-08。对应当前工作区代码，未部署到远端。

## 1. 已接通的路径

学生进入工作区并确认记录说明 → 建立实验 run → 生成题目并保存私有判分快照 → 实际显示题目 → 提交原始答案 → 数据库事务判分与写入事件 → 教师按实验、班级汇总。

学生向学习 Agent 提问 → 保存请求和会话 → 保存导师回复 → 前台打开的聊天区域渲染回复后发送展示确认 → 之后的提交固定记录帮助状态。

教师首页继续只显示参与学生、练习提交、提交正确率和知识点表现。展开详情显示难度与帮助状态的正确率、各组提交数，以及有效导师轮次的模型推理分布。教学助手使用与看板相同的 `learning` 范围。

## 2. 启动及持久化

沿用项目现有启动方式。例如，在仓库根目录：

```powershell
$env:LEARNING_EXPERIMENT_ID = 'pilot-v1'
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

另一个终端进入 `student-frontend`：

```powershell
npm.cmd run dev -- --host 127.0.0.1
```

也可以先在 `student-frontend` 执行 `npm.cmd run build`，再直接访问后端地址，由后端提供构建好的界面。修改前端后需重新构建。

- 配置了 `DATABASE_URL`：使用现有 SQLAlchemy 引擎，新增两张表，不覆盖旧表。生产 PostgreSQL 路径使用事务级 advisory lock。
- 未配置 `DATABASE_URL`：使用 `data/learning.sqlite3`，重启进程后记录仍在。该文件及其日志已加入 Git 忽略。
- 启动时自动 `create_all`。当前只新增表，不需要清空数据。它不是后续任意结构变更的迁移工具。
- 所有后端实例必须使用相同 `LEARNING_EXPERIMENT_ID` 和共享数据库。切换实验编号会隔离统计，不删除历史记录；学生需刷新重新连接。
- SQLite 用于本机或单实例试验。跨实例部署使用共享数据库；当前事务串行化适合首轮小规模采集，尚未做高并发容量测试。

教师选择与学生相同的班级，然后点击“刷新”。班级选项来自 `/classes`，包含 Demo、A 班和 B 班。看板标明实验编号与指标版本，不会混入旧 JSON 日志或模拟样本。

学生工作区必须先成功读取真实班级列表，才会恢复或发起学习记录。列表暂时不可用时展示“重新加载班级”，不回退到演示数据；旧的 `class-a/class-b` 等无效缓存会退回“请选择班级”，由参与者选择实际班级，不自动归入 Demo 或其他班级。`/learning/config` 同时返回权威班级列表，在开始记录前再次校验；若班级已下线，重新加载列表。该流程已通过班级接口失败、旧缓存、延迟加载、有效 run 恢复和班级配置变更的浏览器回归。

## 3. 实际数据结构与关联

本轮用两张新表承载最小数据链路，尚未将设计稿中每类实体拆成独立关系表。关联通过服务端事务和所有权校验维护，没有数据库外键。

`learning_records_v2`：

- `id: String(100), PK`：实体编号。
- `kind: String(32)`：`run / exposure / attempt / challenge / dialog / reply`。
- `owner: String(64)`：参与者随机凭据的 SHA-256，不保存明文凭据。
- `payload: JSON`：该实体的不可变提交快照或可变运行状态。

`learning_events_v2`：

- `id: String(100), PK`：事件幂等编号。
- `experiment_id: String(100)`、`class_id: String(80)`：可索引的统计范围。
- `created_at: Float`：服务器 Unix 时间（秒）。
- `payload: JSON`：包含 `schema_version=2`、`event_id`、`event`、`ts`、`run_id`、`student_id`、`class_id`、`experiment_id` 和事件专有字段。

主要实体字段：

- run：`run_id: UUID string`、`student_id: hash string`、`class_id`、`experiment_id`、`started_at: float`、`consent_version`、`status='active'`。
- exposure：`exposure_id: UUID string`、`run_id`、`question_id`、`mode: free/challenge`、私有 `question` 快照、`presented_at: float|null`、`attempt_count: int`、请求编号列表、已展示有效回复编号列表。
- attempt：`attempt_id: UUID string`、`exposure_id`、原始 `answer: JSON`、`attempt_no: int`、`submitted_at: float`、`assistance_status`、`result: JSON`。
- challenge：`submission_id: UUID string`、锁定的题次与答案清单、按题返回的结果。未作答项为 null，不计入提交正确率分母。
- reply：`request_id: UUID string`、请求正文、run/题次编号、`started_at`、完整回复、`presented_at` 或失败状态。dialog 保存消息历史、轮次和待处理请求。

生成后记录 `question_assigned`。题目进入前台作答界面后发送 `question_presented`，提交答案前也会确保题次已确认显示。预生成和预取只记分配。显示确认失败时可用相同 exposure 重试。生成题目已复制到 exposure 后，不再依赖最近 2000 题缓存判分；尚未建立快照且已失效的旧题会明确提示更换。

每次 `practice_grade` 保存原始答案、正确性、题次内提交序号 `attempt_no`、题型、难度、小节、来源、语言、帮助状态、判分版本和 `elapsed_ms`。新提交使用 `grader_version='rules-v3'`，填空支持精确等值的有理数表达式，例如 `6/4`、`1.5` 和 `3/2`。一般符号等价仍依赖题目的标准答案及可接受别名。旧提交保留原判分版本和结果。`elapsed_ms` 是服务器首次收到显示确认到本次提交的墙钟间隔，包含离开、休息和后台时间，也受确认请求延迟影响。

导师事件包括 `tutor_requested`、`session_start`、`turn`、`tutor_response_presented`，捕获的调用异常另有 `tutor_failed`。新请求的 `student_text` 保存该轮提问，`submitted_attempt_id` 单独引用同一题次已提交的答案。该答案只作为模型上下文。请求内容和导师回复属于研究原始数据，教师聚合接口不返回这些文本。

## 4. 接口与一致性

- `GET /learning/config`：当前实验编号和记录说明版本。
- `POST /learning/start`：确认记录并创建/恢复 run。
- `POST /learning/exposures`：保存题次快照；`presented=false` 仅分配，true 确认显示。
- `POST /learning/attempts`：自由练习提交。
- `POST /learning/challenges`：整轮挑战一次事务交卷，含未作答项。
- `POST /learning/tutor`：导师请求及可重放结果。
- `POST /learning/replies/{id}/presented`：回复展示确认。
- `GET /analytics/class?scope=learning&class_id=...`：新看板统计。
- `POST /analytics/ask`，携带 `scope='learning'`：相同范围的教学助手。

学习写接口使用 `X-Learning-Token` 校验记录所有权。服务端拒绝用其他凭据提交/读取已有题次；run、题次、班级、当前实验之间必须一致。它是浏览器随机凭据机制，不是学校账户登录或教师权限系统。

浏览器在请求发送前将唯一编号与答案快照写入 localStorage。相同提交编号重放返回原结果；相同编号换答案返回 409。数据库将判分、题次计数和事件写入放在同一事务中。学生收到成功结果后，下一次主动重试使用新的提交编号。

响应丢失后刷新并重新提交，会恢复上次请求的答案和结果，不重复增加教师端次数。如用户已改选答案，先恢复旧结果并提示，再主动提交新答案。浏览器存储写入失败时不应继续发送无法可靠重试的请求。

挑战统一提交答案快照。任一道题验证失败时整轮回滚；成功后所有答案锁定，重复交卷返回同一结果。未展示且未作答的题记录为 `question_skipped(presented=false)`。未填完整的答案在交卷时以 `reason=incomplete` 和 `draft_answer` 留存，供回看和研究。两类跳题均排除在已判分提交之外。界面及新导师接口均在挑战交卷后开放本题帮助。

导师调用在数据库写事务外执行，避免网络等待持有数据库锁。相同 request ID 成功后返回同一回复；处理中的请求返回 409；失败保留记录，提示重新提问。超过 300 秒的待处理请求允许后续新请求接替，旧请求迟到不得覆盖新会话。该超时是运行恢复阈值，不是行为指标。

## 5. 教师指标口径

所有指标限定当前 `LEARNING_EXPERIMENT_ID` 和所选班级；不统计 legacy 日志。版本 `pilot-v2`。

1. 参与学生：有至少一条成功提交或 `tutor_requested` 的 `student_id` 去重并集。只打开页面、仅生成题目不计；请求后 AI 失败仍属于参与。
2. 练习提交：成功提交事件数。包含首次和主动重试，排除网络重放、未作答和验证失败。
3. 提交正确率：正确提交数 / 成功提交数。无提交时界面显示“—”。
4. 知识点表现：同一知识点的正确提交 / 全部成功提交；样本数与首页提交总量可以相互核对。
5. 难度 × 帮助状态：每个难度、每组的正确提交 / 该组成功提交，同时显示组内次数。
6. 模型推理分布：有效导师轮次中各等级的数量 / 有效轮次数。排除 AI 不可用、被阻止及带安全回退标记的轮次，保留模型评为 `none` 的正常轮次。

帮助状态在提交事务内冻结：

- `none`：本题次提交前没有导师请求记录。界面称“未记录本题 AI 帮助”，不能证明学生没有使用外部 AI、教材或另一题次的帮助。
- `received`：本题次至少一条有效回复已获展示确认。
- `unknown`：有请求，但尚无有效回复展示确认，包括回复未显示、确认失败、请求失败或回退。未知组单独列出，不并入独立作答。

提交后的求助不反写先前 attempt。首次定义为题次内 `attempt_no=1`，不是该学生人生中第一次接触知识点。重试为同一 exposure 的后续成功提交。重新开始或新题次允许再次出现同一题目。

## 6. 当前边界与实验使用

- 已实现的是核心记录、判分、AI 关联和班级汇总。没有声称完成设计稿全部 P0/P1。
- 页面导航和未提交草稿目前保存在本浏览器。新工作区不再用未经身份验证、仅凭姓名的旧 `/progress` 接口覆盖本地状态；旧接口留给旧客户端兼容。跨设备身份恢复与服务端草稿同步尚未实现。最终已提交答案和事件保存在数据库，不依赖本地页面进度。
- 匿名者拥有随机浏览器凭据。同一浏览器同一参与者代号恢复原凭据；不同设备不会自动合并。共用设备必须切换代号。清除浏览器存储会失去恢复凭据，不会自动删除服务端数据。
- 已增加采集告知和同意动作，尚无完整研究同意管理、撤回删除接口、保留期自动清理、研究员导出权限或教师登录鉴权。这些需在正式招募与公共部署前落实；当前适合受控联调和试运行。
- run 暂未实现明确结束、心跳或退出事件，`active` 不能解释为仍在线。中途退出仅留下截至最后成功记录的轨迹，不能推断退出原因或把无记录当零表现。
- 挑战限制只针对新页面与新接口中的本题次；保留的旧接口、其他题次和外部工具不受监考式管控。不能宣称已经实现严格无 AI 对照组。
- 尚未实现研究导出、首次正确率/最终题次结果报表、前后测或条件随机分配。底层 attempt/exposure 可以支持后续计算。
- 知识点、难度、模型推理等级和正确率都只是当前任务中的行为线索，不能直接解释为能力或学习提升。
- 新 SQL 表目前以 JSON 快照为主。后续正式研究可根据查询、审计、外键及导出要求拆表；不得把设计稿中的拟议字段当成已经部署。

本轮验收结果：上述 37 项相关测试通过，前端生产构建通过；浏览器联调使用真实页面、HTTP 接口和临时 SQLite，仅用确定性题目/导师替身隔离模型依赖。已验证响应丢失后刷新重试不重复计数，AI 展示确认后的提交归入正确分组，挑战未作答不计为错误提交，以及教师端班级隔离。未向真实实验数据库写入这些测试样本。构建仍有既有的大包体积提示，不影响本次构建通过。

手工验证：学生选择 A 班，同意记录，提交一次错答，再向导师求助并改对；教师选择 A 班并刷新，应看到 1 名参与者、2 次提交、50% 正确率。若有效回复展示已确认，详情应分别显示未记录帮助 0%（1 次）、已获得帮助 100%（1 次）。切至 B 班不应出现 A 班数据。

## 8. 章节挑战出题修复（2026-11-08）

原来的章节挑战复用了普通练习的随机模型出题流程。许多小节缺少指定题型的本地题；模型不可用、题目未通过校验或返回重复内容时，带有历史排除题干的请求会报“没有更多新题”。这不是学生应通过切换设置解决的问题。

现在 `/generate` 接受 `purpose='challenge'`，使用 `backend/challenge_questions.py` 中按小节编写的参数化数学题。覆盖现有 8 章、51 个小节、4 种题型及中英文；无需模型或 RAG 服务即可生成整套挑战。每小节一道题、中等设计难度和混合题型的界面约定保持一致。再次挑战更换题目参数，在接口允许的 50 条历史排除范围内避免重复题干。重复的数学结构仍然可能出现，不应将其解释为平行测验已经等值。

题目保留具体解题步骤和精确答案，使用现有校验与服务端判分。另修正导数选择题校验器：求某一点的导数时，先代入该点再比较数值选项，避免把正确题目误判为无有效答案。旧的未完成挑战继续进入时会自动补齐剩余题目，不清除已保存的题目与答案。

私有题目快照和新提交事件均记录 `generation_method='challenge-template-v1'`；研究时可据此与旧模型/题库生成数据分开。当前“中等”是设计标签，不是经过样本标定的难度；正式研究仍需要教师审核题目覆盖及难度。章节挑战与普通练习的生成方式现在不同，比较两者结果时须考虑这一差别。

验收：495 项相关测试通过，包括 408 个小节×题型×语言组合、数学计算与判分校验，以及最大历史排除量下仍可生成新题。浏览器实际完成了 8 章全部 51 题的准备、逐题切换和第一章重新开始。当前 5173 页面代理的真实挑战出题接口也已验证返回 200。

## 9. 模拟初学者的三方核对

本次已修复等值有理数填空误判、挑战部分答案丢失，以及导师原始输入与附加作答上下文混合的问题。另补充答案字段和类型校验，拒绝布尔值冒充选项编号、题型不符的额外字段，以及将完整答案作为跳题草稿提交。前台题目展示确认与后台预取分开。服务端明确返回 422 时，前端释放被拒绝请求的编号，允许修改后重新提交。

用实际学生界面、后端接口和教师页面，在独立 SQLite 中模拟四位参与者。普通练习和导师回复使用固定样本，章节挑战使用题库模板和一道专门验证部分填空的测试题。用只读 SQL 独立检查身份、班级、题次、提交、题目快照、原始答案、判分、事件顺序和分组，再与教师端比较。

- A 班模拟一位答题并提问、一位仅提问、一位仅看题。教师端显示 2 位参与者、6 次提交、答对 4 次（67%）。其中未记录本题帮助 2/4，已展示有效帮助 1/1，帮助状态未知 1/1。B 班单独显示 1 位参与者、1 次提交、答对 1 次（100%）。
- A 班四道已判分题的首次提交答对 2/4，两次重试均答对，按每题最后一次提交复算为 4/4。教师主页统计的是全部提交，分母为 6。挑战另有一题只填第一空、一题未展示，两条跳题均留存。
- 模拟断网丢失一次提交的响应，刷新重发后数据库仍只有一条首次提交。先提交再打开已生成的 AI 回复时，提交仍保留“帮助状态未知”。挑战交卷后提问也不反写该题的帮助状态。
- A 班收到 5 条导师回复，其中 1 条服务回退。教师端的 4 个有效样本对应未体现 25%、较弱 25%、部分 50%。这些等级按轮次统计。回复展示事件只表明界面确认展示，无法确认学生是否读懂。
- 核对本机原有默认 SQLite 时仅有 2 条开始记录、10 条分配和 1 条展示，尚无提交或导师轮次可供历史抽查。模拟数据单独保存。

最终验证通过 554 项相关测试、前端生产构建、浏览器完整流程和独立 SQL 复算。当前开发地址的 `/api/learning/config` 返回有效实验编号和班级列表。构建保留已有的大包体积提示。
