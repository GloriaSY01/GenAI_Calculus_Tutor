# 代码检查与导师教学机制修改建议

- 日期：2026-11-01
- 检查版本：main，`872d045`
- 范围：出题与判分、导师对话、学生端浮动助手、章节挑战、相关数据接口。
- 本文仅记录问题与建议，不代表已经实施修改，也不是全项目无遗漏审计。

## 一、验证情况与限制

- 已阅读相关前后端代码，并对输入拦截、答案泄露检查和提示推进进行了隔离复现，没有调用真实模型验证这些复现。
- `tests/test_socratic.py` 与 `tests/test_content_quality.py` 共 11 项测试通过。既有测试通过不代表覆盖了本文发现的边界情况。
- 当前 yolo8 环境缺少 `sqlalchemy`，导入新版后端及收集数据库、生成器相关测试失败。依赖已经列在 requirements.txt，属于拉取代码后的环境依赖未同步问题。
- 未完成完整后端测试及浏览器端到端验证。下文明确区分代码检查结论与已复现结果。
- 本次仅新增本文档，不修改业务代码，不安装依赖。

## 二、发现的问题

### 1. 高优先级：章节挑战交卷前仍可使用学习助手

位置：
- `student-frontend/src/pages/StudentWorkspace.jsx`：页面底部挂载 StudentAgent、判分提交和挑战结果记录。
- `student-frontend/src/pages/StudentAgent.jsx`：以当前题目创建导师会话。

页面说明交卷后开放导师，但 StudentAgent 始终挂载，并接收当前题目，没有根据未提交的挑战状态限制使用。它也没有将辅助使用情况回传到题目的 assisted 标记。学生可能在挑战中获得提示，而判分记录仍显示为独立作答。

验证依据：代码路径检查，尚未进行浏览器复现。

建议：
- 未提交的挑战限制针对当前题目的指导；浮动助手可以仅提供操作帮助。
- 题下导师和浮动助手统一记录辅助状态，后端关联题目、学生和本次作答，不能只相信前端提交的 ai_assisted。
- 明确离开挑战去学习后的记录规则，避免接受题目指导后仍统计为独立完成。

验收：交卷前不能从其他助手入口获得当前题目的提示；任何入口产生的帮助都能正确关联作答记录。

### 2. 高优先级：解释后解锁提示的限制不完整

位置：`backend/socratic.py`，process_turn 的教学策略执行和理解度更新部分。

目前只有模型动作是 advance 或 complete 时，后端才检查解释是否达到 adequate/strong。模型返回 hint 时，即使解释是 weak，也可能继续提示和增加理解度。

隔离复现：模拟返回 ASSESSMENT=weak、ACTION=hint、MASTERY_GAIN=yes，得到 hint_level=1、mastery=10。复现证明后端状态转换存在缺口，不代表真实模型每次都会如此返回。

建议：
- 后端统一决定能否推进、是否加分，不以动作名称作为唯一限制条件。
- 区分“不推进解题步骤的澄清帮助”和“透露下一步骤的新提示”。解释不足时可以帮助学生理解，不应机械拒绝所有帮助。
- 同一步的相同证据不能重复获得理解度增量。

验收：弱解释不能仅通过动作标记变化获得进度或加分；有效澄清仍可正常提供。

### 3. 中优先级：输入误拦截与输出漏检

位置：`backend/guardrail.py`；`backend/socratic.py` 的输入检查、输出检查与模型复核。

已复现：
- `Do not tell me the answer.` 被判为 answer_begging，未理解否定含义。
- 参考答案为 `2x`，回复 `Try writing $2x$ in the box.` 未被字符串输出检查识别为泄露。

补充：默认开启的模型复核可能补救部分漏检，但不能证明字符串检查可靠；没有固定题目的自由聊天跳过基于参考答案的输出检查和复核。

建议：
- 区分索要答案、核验学生自己的答案、要求不要给答案、概念解释和修改系统指令。
- 结合题目、学生已完成的步骤和当前帮助阶段判断，不只匹配关键词。
- 输出检查结合数学表达式及语义，不能只依赖参考答案原字符串。
- 已由学生正确给出的答案应允许确认，不能一律认定为泄露。

验收：否定句不误拦；中英文及常见等价表达有覆盖；确认学生答案与替学生作答能够区分。

### 4. 中优先级：数学等价填空答案可能判错

位置：`backend/generator.py`，_norm 和 grade 的 fill_blank 分支。

当前主要通过去空格、美元符号和转小写后匹配预设字符串。标准答案仅为 `2*x` 时，`x+x` 不会被识别为正确，除非预设备选答案包含它。

验证依据：判分代码检查；生成器相关测试因缺少 sqlalchemy 未能运行。

建议：按题目要求处理数值误差、表达式等价、积分常数及单位。应保留定义域等约束；无法可靠判断时返回待核验状态，不能仅交给模型随意判定，也不能直接判错。

验收：覆盖等价形式、非等价形式、定义域限制和数值容差等案例。

### 5. 中优先级：浮动助手的 LaTeX 没有渲染

位置：`student-frontend/src/components/FloatingAgent.jsx` 的 message.content 渲染。

后端要求使用 LaTeX，但该组件使用普通 p 标签展示回复，未使用现有数学渲染组件。含数学分隔符和命令的回复会以普通文本显示。

验证依据：组件代码检查，未进行浏览器截图验证。

建议：统一采用项目已有的数学渲染方式，并检查行内公式、块公式及长公式布局。

### 6. 部署前必须处理：接口缺少身份与权限验证

位置：`backend/main.py` 的作业创建/删除、收藏和进度读写等接口。

检查到这些接口没有验证登录身份、教师角色及学生本人身份。界面中的角色切换、传入 student_id 或 class_id 都不能代替服务端授权。

建议：
- 作业操作校验教师角色及班级归属。
- 学生只能读写自己的收藏和学习进度。
- 不应直接信任客户端提供的身份标识。

验收：未登录、跨学生和跨班级请求分别被拒绝；合法操作仍可完成。

### 7. 当前本地运行阻塞：依赖尚未同步

位置：`backend/database.py` 导入 sqlalchemy；依赖声明位于 `requirements.txt`。

当前 yolo8 环境报 `ModuleNotFoundError: No module named 'sqlalchemy'`。即使不配置数据库，模块导入也需要该依赖。

建议：在后续实际修复与启动前同步项目依赖，再运行数据库、生成器及完整后端测试。此项是环境问题，不应误记为依赖文件漏写。

## 三、防止直接索要答案的教学设计建议

### 1. 目标

控制帮助程度，准确记录帮助使用情况，同时让真正不会的学生能够继续学习。不要把目标简化为增加拒绝关键词或永远禁止展示答案。

### 2. 按学习场景设置规则

#### 概念学习

- 可以直接解释概念、规则和适用条件。
- 可以使用不同于当前练习题的例子帮助理解。
- 不要求每个知识性问题都先回答“为什么”。

#### 自由练习

- 鼓励学生先尝试，但不把不会表达理由当作拒绝帮助的依据。
- 按需提供方向、关键规则、局部步骤，逐渐增加帮助。
- 持续卡住时允许进入讲解学习，将该题记录为辅助完成或已查看讲解，不冒充独立掌握。
- 讲解之后提供一道同类新题，用独立作答验证理解。

#### 章节挑战

- 提交前不提供当前题目的解题指导，仅提供操作说明。
- 允许退出学习并保存进度，但需明确帮助使用后的结果归类。
- 提交后开放教材、导师和复盘。
- 将挑战定位为学习自检，避免宣称能够阻止学生通过其他工具获取答案。

### 3. 直接索要答案时的交互

避免重复固定回复“我不能给答案，请先解释为什么”。先帮助学生定位障碍，例如：

> 我们先找出卡住的位置：你是不理解题意、不知道用哪条规则，还是计算到一半遇到了问题？

之后提出具体且可回答的小问题，例如“这里能否看成外层函数和内层函数？”，而不是持续要求学生笼统描述想法。

### 4. 后端需要统一管理的状态

- 当前题目及本次作答身份。
- 当前学习模式和是否已提交。
- 已提供的帮助阶段、帮助内容及使用入口。
- 学生已经完成或解释过的步骤。
- 是否查看过讲解，是否仍属于独立作答。
- 理解度增量对应的具体证据，防止重复计分。

模型提出指导建议，后端执行允许的状态转换。提示次数、作答正确率和理解度应分开记录；聊天更多或请求更多提示不等于理解更深。

### 5. 同一题目只维护一套教学规则

题下导师与浮动助手使用同一份题目状态和辅助记录。切换入口、语言或重新创建会话，不应无意中重置帮助限制或清除辅助标记。

## 四、建议实施顺序

1. 同步本地依赖，恢复可运行、可测试的基线。
2. 修复挑战助手入口和辅助记录，保证独立作答统计可信。
3. 修复提示推进、理解度加分和重复证据处理。
4. 改善误拦截、输出检查及卡住后的教学引导。
5. 改进填空等价判分和浮动助手公式渲染。
6. 在正式面向学生部署前完成身份与权限校验。

后续修改时应分别验证功能正确性和教学体验；不能仅以模型成功返回回复或既有单元测试通过作为完成标准。
