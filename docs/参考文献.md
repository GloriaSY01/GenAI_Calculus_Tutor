文献 1
Boosting Large Language Models with Socratic Method for Conversational Mathematics Teaching
1. 论文核心内容
 这篇文章研究如何将苏格拉底式教学方法引入大语言模型的数学教学场景中，使模型不再直接输出答案，而是通过对话一步步引导学生思考。文章提出了一个面向数学教学的 SocraticLLM，并结合额外知识增强模型回答的可靠性和教学质量。

2. 与我们项目最相关的设计点
 这篇文献和我们项目中 右侧 AI tutor 的引导式交互设计 高度契合，特别对应以下几个点：
不直接给答案，而是逐步引导
agent回复需要有教学阶段感，而不是普通聊天
agent在数学场景下要兼顾“引导性”和“正确性”
3. 可借鉴的核心机制
将 tutoring 拆分为更明确的教学环节，如 review、heuristic、rectify、summarize
在数学场景中引入知识增强，减少模型幻觉
用结构化的教学流程替代单纯 prompt 限制
4. 对我们项目的启发
 我们目前的agent已经实现了基础的 Socratic prompt 约束，但还比较粗。参考这篇文章，后续可以把 agent 的对话策略细化成更明确的教学阶段，例如：
先回顾知识点
再提出启发式问题
对错误思路进行纠正
最后做总结
   这样可以让我们的agent更像“真正的教学tutor”，而不是简单的问答机器人。

M1 Dialogue Manager
M2 Guided Response Generator
explain-to-unlock / 苏格拉底式交互逻辑设计

ZOU JINGTING
文献 1
MathTutorBench: A Benchmark for Measuring Open-ended Pedagogical Capabilities of LLM Tutors (EMNLP 2025 Main) 

1. 论文核心内容
这篇论文提出了 MathTutorBench，一个用于评估 LLM 数学 tutor 教学能力的 benchmark。论文指出，一个模型会解数学题，并不代表它会教学生。很多 LLM 虽然数学解题能力强，但在真实 tutoring 场景中，可能无法正确理解学生错误、无法给出合适提示，或者容易直接把完整答案讲完。
因此，论文从数学 tutor 的角度，将模型能力拆成三类：数学专业能力、学生理解能力、教学回应生成能力。这种拆分强调 tutor agent 不仅要有正确的数学知识，还要具备理解学生思路和生成合适教学反馈的能力。

2. 与我们项目最相关的设计点
- agent 不能只保证数学答案正确，还要具备教学能力。
- agent 需要理解学生当前解题过程，而不是只判断最终答案。
- agent 需要识别学生错误，并给出合适的 scaffold / hint。
- tutor 回复需要控制信息量，避免一次给出过多内容，影响学生自主思考。

3. 可借鉴的核心机制
- 将 tutor 能力拆成多个维度，而不是只看模型是否会解题。
- 关注 student understanding，即模型是否能判断学生思路是否正确、错误出现在哪里。
- 关注 pedagogical response generation，即模型是否能生成合适的教学提示。
- 使用 reward model 区分专家教师回复和普通回复，说明 tutor 回复质量可以被系统性评价。

4. 对我们项目的启发

我们当前的 tutor agent 已经能够进行基础引导，但后续不能只关注“是否回答正确”，还应关注它是否像一个合格 tutor 一样理解学生、定位错误、控制提示强度。
参考这篇论文，我们可以把 tutor agent 的设计重点从“会不会回答微积分问题”扩展为“是否具备教学能力”。例如，M1 Dialogue Manager 需要判断学生当前处于哪一步，M2 Guided Response Generator 需要生成既不剧透又能推进学生思考的回复。

 5. 这篇文献支撑的项目设计点
- M1 Dialogue Manager
- M2 Guided Response Generator
- 学生解题过程理解
- 错误识别与纠正
- tutor agent 教学能力评估

文献 2
Training Turn-by-Turn Verifiers for Dialogue Tutoring Agents: The Curious Case of LLMs as Your Coding Tutors( Findings of ACL 2025) 

1. 论文核心内容
这篇论文提出 TRAVER，用于提升对话式 tutor agent 的可靠性。它认为 tutor agent 每一轮回复都应该真正推动学生完成任务，而不是只生成一段看起来合理的回答。
TRAVER 包含两个关键部分：一是追踪学生当前知识状态，二是用 turn-by-turn verifier 检查并选择更合适的 tutor 回复。虽然论文场景是 coding tutor，但它提出的“学生状态追踪 + 每轮回复验证”机制可以迁移到微积分 tutor。

2. 与我们项目最相关的设计点
这篇文献主要对应我们的 M1 Dialogue Manager。我们的 tutor agent 也需要在每一轮中判断学生当前处于什么状态，然后决定下一步应该追问、提示、纠错还是推进。
它强调对话管理器不只是保存聊天历史，而是要根据学生表现动态选择下一步教学动作。

3. 可借鉴的核心机制
- 在回复前先估计学生当前掌握情况。
- 为每一轮 tutor 回复做质量判断。
- 可以生成多个候选回复，再选择最能推进学习的一条。
- 将 tutoring 看成一个逐轮推进任务完成的过程，而不是普通聊天。

4. 对我们项目的启发
我们可以在现有 agent 架构中加入轻量级的回复检查机制。例如检查 agent 回复是否直接泄露答案、是否只给一个小步骤、是否符合当前学生状态、是否有助于学生继续思考。
这可以提升 tutor agent 的稳定性，避免模型偶尔给出过度提示或直接答案。

5. 这篇文献支撑的项目设计点
- M1 Dialogue Manager
- 学生状态追踪
- 教学动作选择
- 回复质量检查
- 自适应提示策略

文献 3

Cognitive Engagement in GenAI Tutor Conversations: At-scale Measurement and Impact on Learning (AIME-Con 2025) 

1. 论文核心内容
这篇论文研究如何分析学生在 GenAI tutor 对话中的认知参与度。它指出，学生使用了 tutor 并不代表真正参与了学习；只统计对话轮数、使用时长等行为数据是不够的，还需要分析学生是否在解释、推理、反思和修正。
论文使用 LLM-as-judge 方法，对学生对话内容进行认知参与度分类，并分析这种参与度与后续学习表现之间的关系。

2. 与我们项目最相关的设计点
这篇文献和我们项目的学习分析、日志记录、学生面板设计相关。我们的 tutor agent 不应只记录学生是否完成题目，还应记录学生在交互过程中是否真的进行了有效思考。
它提醒我们，对话日志本身可以成为学习过程数据，用来分析学生是否从被动回答逐渐转向主动推理。

3. 可借鉴的核心机制
- 将 tutor 对话内容作为学习过程数据。
- 区分学生是被动参与、主动尝试，还是能够建构性地解释和修正。
- 使用 rubric 或 LLM-as-judge 对学生输入进行结构化分析。
- 将学生对话过程与后续学习表现联系起来。

4. 对我们项目的启发
我们可以在 tutor agent 的日志中，不只保存学生原始输入，还对输入进行结构化分析。例如学生是否给出了解释、是否体现推理、是否修正了错误思路。
这样学习分析就不只是“学生用了多久、做了几轮”，而是能够反映学生在交互中的思考质量。

5. 这篇文献支撑的项目设计点
- 学习分析 Dashboard
- 学生输入质量分析
- 学生认知参与建模
- 学习过程数据记录
- tutor agent 教学效果分析

文献 1：（EMNLP 2024 Findings）
[2402.15861] MATHWELL: Generating Educational Math Word Problems Using Teacher Annotations 

1. 论文核心内容

这篇文章研究如何用大语言模型自动生成 K-8 阶段的数学应用题，并强调题目要真正“能用于教学”必须同时满足三点：可解（solvable）、答案准确（accurate）、教育适当（appropriate）。作者发现现有公开模型/数据集常常做不到这三点，于是用教师标注构建高质量数据集，微调 Llama-2 (70B) 得到 MATHWELL；专家评估显示其在可解性、准确性、适当性上明显优于公开模型，质量接近 GPT-4。它还借助 Program-of-Thought（让题目附带可执行的解答程序）来保证答案的正确性。

2. 与我们项目最相关的设计点

- 出题不是“随便生成”，而要保证可解、答案正确、适合教学
- 生成内容的“答案”必须是可验证的，而不是模型自说自话
- 需要用质量标准（而不仅是流畅度）来评判生成结果

3. 可借鉴的核心机制

- 把“可解性 / 答案准确性 / 教育适当性”作为生成的硬性质量标准
- 用 Program-of-Thought / 代码执行让题目自带可验证答案
- 用少量专家标注来校准自动评估

4. 对我们项目的启发

我们当前的生成器直接让 LLM 出题，已经出现“答案不正确、选项错误”等问题。可借鉴 MATHWELL，把“答案可由代码/CAS 执行验证”纳入生成流程，并用一小批专家标注来校准我们的自动评分标准。

5. 这篇文献支撑的项目设计点

- M3 内容生成器（Content Generator）
- M5 内容验证器（Content Validator，质量标准）

文献 2：[2506.00963] From Objectives to Questions: A Planning-based Framework for Educational Mathematical Question Generation 

1. 论文核心内容

这篇文章针对“生成符合教育目标的数学题”，构建了带多维教育目标标注的 EduMath 数据集（约 16k 题），提出 EQGEVAL 评测（三个评估维度），并提出 EQPR 方法：借鉴教师“计划—评估—优化”的出题过程，把蒙特卡洛树搜索（MCTS）与 LLM 结合，通过 Critic（评估）+ Reflection（反思）两个模块对题目进行迭代优化，使其同时满足多维教育目标。


2. 与我们项目最相关的设计点

- 出题要先明确“教什么、达到什么目标”，再生成
- 生成不是一次成型，而是“评估—优化”的迭代过程
- 要用多维教育目标（而非单一题面质量）来指导生成

3. 可借鉴的核心机制

- “plan-evaluate-optimize”闭环：先规划教育目标 → 生成 → 评估 → 优化
- Critic + Reflection 双模块：评估并给出明确的修改方向
- 用多维教育目标驱动生成，便于难度与覆盖控制

4. 对我们项目的启发

我们可以把出题从“一次性 prompt”升级为“规划 → 生成 → 验证 → 再生成”的迭代闭环（正好与导师建议的“内容验证 + 不通过则重生成”一致），并为每道题显式声明教育目标/知识点，方便后续做难度控制与题库覆盖统计。

5. 这篇文献支撑的项目设计点

- M1 知识点组织器（Knowledge Organizer）
- M4 难度控制器（Difficulty Controller）
- M5 内容验证器（迭代优化闭环）

文献 3：EDM 2025
Multi-Agent Collaborative Framework For Math Problem Generation 

1. 论文核心内容

这篇文章提出一个协作式多智能体框架，把“推理时计算（inference-time computation）”引入自动出题（AQG）：让多个 agent 迭代精修“题目—答案对”，以更好地平衡题目的复杂度与认知需求；并用五个元评估维度——relevance（相关性）、importance（重要性）、clarity（清晰度）、difficulty matching（难度匹配）、answerability（可作答性）——来评估生成质量。初步结果表明多 agent 协作能产出更可控、更有教学价值的内容。

2. 与我们项目最相关的设计点

- 难度/复杂度需要被显式控制，而不是碰运气
- 生成质量应有一套明确的评估维度
- 多 agent 分工可提升出题质量

3. 可借鉴的核心机制

- 多 agent 分工、迭代精修，而非单次生成
- 五维元评估标准（可直接作为我们的质量指标）
- 用推理时迭代来提升难度可控性

4. 对我们项目的启发

这五个评估维度可以直接落成我们的量化指标（见下文 2.1）。短期我们可用“生成 → 验证 → 重生成”来近似这一思路；中期可把生成模块拆成“出题 agent / 验证 agent / 难度 agent”协作。

5. 这篇文献支撑的项目设计点

- M3 内容生成器
- M4 难度控制器
- M5 内容验证器
- （未来）多 Agent 协作

文献 4：[2505.20869] Step-Wise Formal Verification for LLM-Based Mathematical Problem Solving 

1. 论文核心内容

这篇文章提出 MATH-VF 框架，用于验证 LLM 数学解答的正确性：Formalizer 把自然语言解答翻译成形式化表示，Critic 集成计算机代数系统（CAS）与 SMT 求解器，对每一步逐句校验；发现错误时给出纠正反馈，并支持“验证 → 反馈 → 再生成”的 refinement。在 MATH500、ProcessBench 等基准上优于已有方法。

2. 与我们项目最相关的设计点

- 不能只看最终答案，要逐步校验
- 要借助外部符号工具（CAS/SMT）保证数学正确
- 验证不通过要能反馈并再生成

3. 可借鉴的核心机制

- Formalizer + Critic 结构：把题目/解答形式化后交给 CAS/SMT 校验
- 逐步（step-wise）验证，而不仅是最终答案——正好覆盖导师说的“解题步骤连贯性”
- 验证不通过即反馈再生成的闭环

4. 对我们项目的启发

这是我们内容验证器的直接蓝本：把生成的题目/解答经“记号归一化”送入 SymPy(CAS) 逐步校验数学正确性与步骤连贯性，失败则反馈重生成；难以符号化的题目降级为数值抽样 / 规则检查。

5. 这篇文献支撑的项目设计点

- M5 内容验证器（核心）
- M3 内容生成（验证—再生成闭环）

1.  论文核心内容

这篇文章研究如何生成对抗性数学应用题。作者用抽象语法树（AST）表示题目结构，通过修改题目中的数值，在尽量保持原题结构、推理路径和难度不变的情况下，生成更容易让 LLM 解错的新题目。

- 用结构化方式表示数学题的解题逻辑

4. 对我们项目的启发

5. 这篇文献支撑的项目设计点

文献 2：Automatic Generation of Socratic Subquestions for Teaching Math Word Problems(EMNLP 2022)

1. 论文核心内容

这篇文章研究如何为数学应用题自动生成苏格拉底式子问题。模型不是直接给答案，而是生成一系列逐步引导问题，帮助学生沿着合理的推理路径思考。论文还使用输入条件控制和强化学习来提升子问题质量。

2. 与我们项目最相关的设计点

 - 生成内容不应只包含题目和答案，也应包含引导性提示

1. 论文核心内容

这篇文章研究多选题中的干扰项生成。作者利用知识库构建候选干扰项，再用 learning-to-rank 方法选择高质量错误选项。好的干扰项应当与正确答案相关、看起来合理，但又不能与正确答案等价或造成歧义。

数学正确性 (Mathematical Correctness)
题目标注的最终答案在数学上是否正确

规则检查：单选恰好 1 个正确项、多选正确项≥1 且不为全部、填空 ___ 数等于答案数；全部满足=1，否则=0

题目是否有明确且可判定的答案
可解=1；欠定、矛盾或无解=0
Demo 题虽然直接代入得到 0/0，但可通过有理化求解，最终有明确答案 1/4，所以可解性通过。
