GenAI 微积分导师

一套「有据可依」的大学微积分 AI 学习系统：以 RAG 检索增强 将回答锚定到 MIT 公开课教材并附引用， 用 苏格拉底式引导 + 解释才解锁 促使学生说清思路而非直接抄答案； 同时为教师提供「学情总览 / 诊断 / 布置 / 数据助手」四大看板，让教与学都可观测、可追溯。

Background

项目背景与痛点

大模型进课堂后，最大的隐患不是「不会答」，而是「答得太快太满」：学生容易直接要答案、跳过推理， 而模型又可能一本正经地编造。本项目围绕「解释驱动学习」重新设计交互，针对以下核心痛点逐一给出方案。

🤖

AI 直接给答案，学生不思考

学生倾向于让模型「把答案给我」，跳过推理过程，练习沦为复制粘贴，学习效果无从谈起。

✦ 方案：解释才解锁（Explain-to-unlock），学生须先说清"为什么/怎么做"，导师才推进下一步提示。
📚

模型幻觉、内容不可溯源

通用大模型可能编造定义与公式，学生无法判断对错，也找不到对应的教材依据。

✦ 方案：RAG 基于 MIT 教材检索，概念卡与导师回答均标注章节、页码与出处引用。
📝

题目脱离教材，质量不齐

随手生成的练习题常与课程进度、教材口径脱节，难度与知识点覆盖难以把控。

✦ 方案：验证教材内容出题 + 受限生成，四种题型围绕已验证章节，服务端判分。
🛡️

易被套答案、易被注入

"直接告诉我结果""忽略之前的规则"等话术会绕过教学意图，让引导式教学失效。

✦ 方案：双向护栏，拦截"索要答案"与提示注入，作答错误也不泄漏正确答案。
📊

教师看不见真实学情

学生在 AI 工具里的表现是黑盒，教师无法知道哪个知识点最薄弱、推理质量如何。

✦ 方案：教师看板，KPI、知识点正确率、推理质量分布、掌握度散点一目了然。
🔬

缺少可复现的评估

教学策略是否有效难以量化，改动后效果好坏全凭感觉，无法做对照实验。

✦ 方案：逐轮日志 + 评估 fixtures，记录推理评分/动作/掌握度，支持 explain vs control 对照。
Learning Loop

学生学习闭环

学生侧以「概念 → 练习 → 导师」三段式聚焦流程串联，每一步都锚定教材、强调思路表达。

01
📖

概念学习

检索 MIT 教材对应章节，生成带引用出处的概念卡，先把定义讲清楚。

02
✍️

练习作答

基于验证内容出题或生成四种题型，服务端判分，错题不泄漏答案。

03
💬

导师引导

苏格拉底式追问，先解释思路再解锁下一条提示，全程可溯源。

Tech Stack

技术栈

前端单页应用 + FastAPI 后端 + Chroma 向量检索；无后端时前端自动回退演示数据，可独立在线预览。

Framework
React 18
函数式组件 + Hooks 构建教师看板与学生学习流。
Build Tool
Vite
极速冷启动与热更新，/api 代理到 FastAPI 后端。
Charts
ECharts
KPI、知识点正确率、推理质量分布、掌握度散点可视化。
Math
KaTeX
概念卡与题目公式渲染，支持上下角标与 LaTeX 排版。
Backend
FastAPI
概念/出题/判分/会话/学情等 REST 接口，服务端判分防泄漏。
Retrieval
Chroma · RAG
MIT 微积分 1–8 章语义检索，回答附章节/页码引用。
Routing / i18n
React Router
SPA 路由 + 中英双语切换 + 明暗主题。
Data
Mock 演示数据
内置真实感演示数据，后端不可达时自动回退，保护隐私。
